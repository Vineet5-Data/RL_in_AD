## 2. Architecture Methodology

### 2.1 P1b — Learned Semantic Vectorization of Road Graph

**Graph Construction:**

Directed multigraph G = (V, E) where V = intersections (OSM nodes), E = road segments (OSM ways split at intersections).

**Raw Feature Assembly per Edge e ∈ E:**

```
x_e^raw = [
    length_e,              # meters (continuous)
    heading_e,             # degrees, sin/cos encoded
    curvature_e,           # derived from geometry
    oneway_e,              # binary
    lanes_e,               # integer
    speed_limit_e,         # km/h (imputed if missing)
    road_type_embed_e,     # learnable embedding lookup for highway= tag
    bridge_e, tunnel_e,    # binary flags
    in_degree_v, out_degree_v,  # for source/target nodes
    poi_agg_e              # POI aggregation vector (see below)
]
```

**POI Aggregation via Distance-Weighted Attention:**

For each segment e with midpoint p_e, retrieve K nearest POIs {q_1, ..., q_K} from Overpass:

$$\alpha_k = \text{softmax}\left(\frac{-d(p_e, q_k)}{\sigma}\right)$$

$$\text{poi\_agg}_e = \sum_{k=1}^{K} \alpha_k \cdot \mathbf{W}_\text{poi} \cdot \text{embed}(\text{type}(q_k))$$

σ = 100m (tuneable radius).

**Graph Transformer (GraphGPS over line graph):**

Convert G to line graph L(G): each edge e becomes a node, connected if edges share an intersection in G.

Apply L layers of GraphGPS:

$$\mathbf{h}_e^{(l+1)} = \text{LayerNorm}\left(\mathbf{h}_e^{(l)} + \text{MPNN}\left(\mathbf{h}_e^{(l)}, \{\mathbf{h}_{e'}^{(l)} : e' \in \mathcal{N}(e)\}\right) + \text{Attn}\left(\mathbf{h}_e^{(l)}, \mathbf{H}^{(l)}\right)\right)$$

Output: **segment embedding** $\mathbf{h}_e \in \mathbb{R}^{256}$ per road segment.

**Design choice**: Line graph vs. heterogeneous graph. Recommendation: start with line graph; add intersection node types in ablation.

---

### 2.2 P1a — Transformer Encoder for Spatiotemporal GPS Sequences

**GPS Observation Embedding:**

For raw observation $o_t = (\phi_t, \lambda_t, t_t)$:

Derive: speed $v_t$, heading $\theta_t = \text{atan2}(\Delta\lambda, \Delta\phi)$, accuracy $\sigma_t$.

$$\mathbf{g}_t = \mathbf{W}_\text{gps} \cdot [\phi_t - \bar{\phi},\ \lambda_t - \bar{\lambda},\ \sin\theta_t,\ \cos\theta_t,\ \log(1+v_t),\ \log(1+\sigma_t)] + \mathbf{b}_\text{gps}$$

Local coordinate normalization $(\bar{\phi}, \bar{\lambda})$ = trajectory centroid.

**Temporal Encoding:**

$$\mathbf{t}_t = \text{PositionalEncoding}(\Delta t_t) + \text{ToD}(t_t \bmod 86400) + \text{DoW}(t_t)$$

**Candidate Road Retrieval:**

$$\mathcal{C}_t = \{e \in E : d_\perp(o_t, e) \leq 50\text{m}\}$$

$$\mathbf{C}_t = [\mathbf{h}_{e_1} + \mathbf{p}_{e_1}^\perp,\ \ldots,\ \mathbf{h}_{e_K} + \mathbf{p}_{e_K}^\perp] \in \mathbb{R}^{K \times 256}$$

**Cross-Modal Transformer (N=6 layers):**

- Self-attention across temporal sequence
- Cross-attention: GPS tokens attend to candidate road embeddings

$$\mathbf{g}_t' = \text{CrossAttn}(\mathbf{Q}=\mathbf{g}_t,\ \mathbf{K}=\mathbf{C}_t,\ \mathbf{V}=\mathbf{C}_t)$$

Output: **joint latent** $\mathbf{z}_t \in \mathbb{R}^{256}$

**Design choice**: Causal vs. bidirectional masking. Recommendation: train bidirectional, distill to causal for deployment.

---

### 2.3 P2 — Latent World Model (DreamerV3-Style RSSM)

State at time t: $s_t = (h_t, z_t)$ where:
- $h_t \in \mathbb{R}^{512}$: deterministic recurrent state (GRU hidden)
- $z_t \in \{0,1\}^{32 \times 32}$: stochastic categorical latent (straight-through gradients)

**Action space**: $a_t \in \{e_1, \ldots, e_{|\mathcal{N}(v_t)|}\}$ — discrete next road segment among topological neighbors. Padded to max-degree D=8, invalid actions masked.

**RSSM equations:**

```
Sequence model (deterministic):   h_t = GRU(h_{t-1}, [z_{t-1}, a_{t-1}])
Representation model (posterior): z_t ~ q_φ(z_t | h_t, enc(o_t))     # uses real GPS obs
Transition predictor (prior):     ẑ_t ~ p_ψ(z_t | h_t)               # imagined, no obs
```

**Road-Conditioned Transition:**

$$h_{t+1} = \text{GRU}(h_t,\ [z_t \| \mathbf{h}_{a_t}])$$

Road segment embedding $\mathbf{h}_{a_t}$ injected into GRU — world model learns motorway dynamics differ from residential.

**Decoder heads:**
1. GPS reconstructor: $\hat{o}_t = \text{MLP}(h_t, z_t)$
2. Speed predictor: $\hat{v}_t = \text{MLP}(h_t, z_t)$
3. Road membership logits: $\hat{\rho}_t = \text{MLP}(h_t, z_t) \in \mathbb{R}^K$

**World Model Training Loss (ELBO):**

$$\mathcal{L}_\text{WM} = \mathbb{E}_{\tau}\left[ -\log p_\phi(\hat{o}_t | h_t, z_t) + \beta \cdot \text{KL}\big[q_\phi(z_t | h_t, o_t) \| p_\psi(z_t | h_t)\big] \right]$$

KL balancing: 80% prior gradient, 20% posterior gradient (DreamerV3).

---

### 2.4 P2 — RL Agent Inside the World Model

**Actor:**

$$\pi_\theta(a_t | h_t, z_t) = \text{softmax}\left(\mathbf{W}_\text{act} \cdot \text{MLP}(h_t, z_t) + \text{mask}_t\right)$$

mask_t zeroes topologically invalid transitions (hard constraint from G).

**Imagined Rollouts (H=15 horizon):**

```
for τ = 0 to H:
    a_{t+τ} ~ π_θ(· | h_{t+τ}, z_{t+τ})
    h_{t+τ+1} = GRU(h_{t+τ}, [z_{t+τ} || h_{a_{t+τ}}])   # world model
    z_{t+τ+1} ~ p_ψ(· | h_{t+τ+1})                        # no real obs
    r_{t+τ} = R(h_{t+τ}, z_{t+τ}, a_{t+τ})                # physics reward
```

**λ-returns and Actor-Critic Update:**

$$R_t^\lambda = r_t + \gamma (1-\lambda) V_\xi(s_{t+1}) + \gamma\lambda R_{t+1}^\lambda$$

$$\mathcal{L}_\text{actor} = -\mathbb{E}\left[\sum_\tau R_{t+\tau}^\lambda\right] + \eta \cdot H[\pi_\theta]$$

### 2.5 P3 — Label-Free Training Signal from Raw GPS

**Constraint 1 — Perpendicular Distance:**

$$r_t^\text{dist} = -\frac{d_\perp(o_t,\ e_{a_t})}{\sigma_\text{GPS}}, \quad \sigma_\text{GPS} \approx 10\text{m}$$

**Constraint 2 — Heading Alignment:**

$$r_t^\text{head} = \cos(\theta_t^\text{GPS} - \theta_{a_t}^\text{road})$$

$$r_t^\text{oneway} = -M \cdot \mathbf{1}[\text{oneway}(e_{a_t}) \wedge |\theta_t^\text{GPS} - \theta_{a_t}^\text{road}| > 90°], \quad M=5$$

**Constraint 3 — Speed Plausibility:**

$$r_t^\text{speed} = -\max\left(0,\ \frac{v_t^\text{GPS} - v_\text{limit}(e_{a_t})}{v_\text{limit}(e_{a_t})}\right)^2$$

**Constraint 4 — Topological Continuity:**

$$r_t^\text{topo} = \mathbf{1}[e_{a_t} \in \mathcal{N}_G(e_{a_{t-1}})]$$

**Constraint 5 — Trajectory Smoothness:**

$$r_t^\text{smooth} = -\left|\Delta\theta_t^\text{GPS} - \Delta\theta_t^\text{road}\right|$$

**Combined Reward:**

$$r_t = \lambda_1 r_t^\text{dist} + \lambda_2 r_t^\text{head} + \lambda_3 r_t^\text{oneway} + \lambda_4 r_t^\text{speed} + \lambda_5 r_t^\text{topo} + \lambda_6 r_t^\text{smooth}$$

Starting weights: $\lambda = [1.0, 0.5, 1.0, 0.3, 2.0, 0.2]$. Topological continuity highest — hardest physical constraint.

---

### 2.6 Unification: Map Matching + Path Prediction

```
At time T (current):
  MAP MATCHING:    argmax_e π_θ(e | h_T, z_T)  →  "which road am I on now?"

At time T+k (future):
  PATH PREDICTION: roll out π_θ inside world model for k steps  →  "which road will I be on?"
```

Same policy network. No separate decoding heads. This unification is a core thesis contribution.

## 3. Training Pipeline

### Stage 0: Road Graph Pretraining (1–2 days, single GPU)

**Goal**: Learn $\mathbf{h}_e$ — semantically meaningful segment embeddings before any GPS data.

**Method**: Graph contrastive learning (GraphCL / BGRL)

**Positive pairs**:
- View 1: drop 20% of POI context features
- View 2: mask 30% of OSM attribute features

**Loss (NT-Xent):**

$$\mathcal{L}_\text{graph} = -\sum_e \log \frac{\exp(\text{sim}(\mathbf{h}_e^{(1)}, \mathbf{h}_e^{(2)}) / \tau)}{\sum_{e' \neq e} \exp(\text{sim}(\mathbf{h}_e^{(1)}, \mathbf{h}_{e'}^{(2)}) / \tau)}$$

**Data**: OSM road network (Geofabrik city extract).

---

### Stage 1: GPS-Road Encoder Pretraining (2–4 days)

**Goal**: Train P1a Transformer to align GPS sequences with road network.

**Data**: T-Drive + Porto raw GPS (no labels). Frozen P1b from Stage 0.

**Multi-task pretraining**:

1. **Masked GPS Modeling (MGM)**: Mask 15% GPS points, predict lat/lon. Loss: Huber.

2. **Contrastive GPS-Road Alignment**:

$$\mathcal{L}_\text{align} = -\log \frac{\exp(\mathbf{z}_t \cdot \mathbf{h}_{e^+} / \tau)}{\exp(\mathbf{z}_t \cdot \mathbf{h}_{e^+} / \tau) + \sum_{k=1}^{N^-} \exp(\mathbf{z}_t \cdot \mathbf{h}_{e_k^-} / \tau)}$$

3. **Next-Point Prediction**: Autoregressive prediction of next GPS token. Loss: MSE.

---

### Stage 2: World Model Training (3–5 days)

**Goal**: Train RSSM to learn trajectory dynamics in latent space.

**Data**: Raw GPS → encoded by Stage 1 → input to RSSM posterior.

**Training**: ELBO on trajectory sequences length 64. Batch size 16. Gradient clip max norm = 100.

**Curriculum**: Start L=16 for first 10k steps → increase to L=64.

---

### Stage 3: RL Fine-Tuning Inside World Model (1–2 days)

**Goal**: Train Actor-Critic (π_θ, V_ξ) using physical-constraint rewards inside imagined rollouts.

**Data**: No new real data — all training inside world model.

- Initialize actor from road membership logits decoder head (warm start)
- 1M environment steps inside world model
- Evaluate against real GPS every 50k steps (Porto held-out test set)
- Early stopping on map matching F1

---

### Stage 4: Evaluation Fine-Tuning (Optional)

Frozen-encoder probe: train small linear head on top of frozen $\mathbf{z}_t$ on 100–500 hand-labeled trips. Measures label-efficiency. Strong ablation for P3 claim.

## 4. Evaluation Protocol

### 4.1 Map Matching Metrics

**Route Matching Fraction (RMF):**

$$\text{RMF} = \frac{|\hat{R} \cap R^*|}{|R^*|}$$

**Mean Horizontal Error (MHE):**

$$\text{MHE} = \frac{1}{T} \sum_t d_\perp(o_t, \hat{e}_t)$$

**Accuracy@K:**

$$\text{Acc@K} = \frac{1}{T}\sum_t \mathbf{1}[e_t^* \in \text{Top-K}(\pi_\theta(\cdot | s_t))]$$

Report K ∈ {1, 3, 5}.

### 4.2 Path Prediction Metrics

**Route Coverage (RC) at horizon H:**

$$\text{RC}@H = \frac{|\hat{R}_{t:t+H} \cap R^*_{t:t+H}|}{|R^*_{t:t+H}|}$$

Report H ∈ {5, 10, 20} steps (~75m, 150m, 300m ahead at 30 km/h).

### 4.3 Baselines

## 5. Compute Constraints (Hard Limits)

All architectural decisions, batch sizes, and training schedules must fit within:

| Resource | Spec |
|---|---|
| **Local GPU** | NVIDIA RTX 4060 — 8GB VRAM |
| **Local CPU/RAM** | 16GB RAM, 1TB SSD |
| **Kaggle** | P100 / T4 (16GB VRAM), TPU v3-8; ~30h GPU quota/week; max 12h per session |
| **Colab** | T4 (free) / A100 (Pro); session time-limited |
| **Multi-GPU** | NOT available — all training single-GPU |

### Implications per Stage

| Stage | Constraint | Mitigation |
|---|---|---|
| Stage 0 — Graph Pretrain | GraphGPS over large OSM graph — VRAM critical | City-level extract only; `torch_geometric` sparse ops; batch by subgraph |
| Stage 1 — GPS Encoder Pretrain | Transformer N=6 over long sequences — memory | Max seq len 128; gradient checkpointing; bf16 mixed precision |
| Stage 2 — World Model (RSSM) | GRU + categorical latents | 16×16 latent (not 32×32); batch size 8–16; sequence len 64 |
| Stage 3 — RL Fine-Tune | Imagined rollouts H=15 — fully in latent space | Cheapest stage; no new data loading |
| Evaluation | FMM baseline on full Porto/T-Drive | Run FMM offline on CPU; cache pseudo-GT before GPU stages |

### Practical Targets

- **Single Kaggle session budget**: ≤12h. Stage 0 and Stage 1 must each fit within one session.
- **VRAM budget**: Peak ≤7.5GB to avoid OOM on RTX 4060.
- **Checkpoint strategy**: Save every 1000 steps — Kaggle sessions can die. Resume from checkpoint mandatory.
- **Dataset loading**: Porto + T-Drive + GeoLife stream from SSD, not preloaded to RAM.

## 7. Key Novelty Claims to Defend

1. **P1b + P1a**: No prior map matching work uses graph contrastive pretraining for road embeddings fed into cross-modal GPS-road attention encoder.

2. **P2**: No prior map matching work uses learned latent world model. All prior RL-based approaches operate in observation space. RSSM enables look-ahead planning over roads without querying GPS.

3. **P3**: All existing deep map matching is supervised. Physical constraint rewards require zero annotation — deployable in any city with OSM + raw GPS (practical BMW use case).

4. **All four together**: Data-efficient (no labeling) + city-agnostic (OSM transfer) + unified matching and prediction in single policy.
