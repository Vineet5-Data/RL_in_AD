# Project Summary — Map Matching + Path Prediction (consolidated 2026-07-11)

> **The single active research doc.** Consolidates four docs now retired to `archive/` (full record, unedited): `archive/critique_and_next_steps.md` (governance, gates, run history) · `archive/methodology-comparison.md` (literature synthesis + all empirical results) · `archive/practical_roadmap.md` (product roadmap) · `archive/run2_capacity_diagnosis_and_scaling_review.md` (capacity diagnosis + scaling literature, full citations).

## 1. What this is

Practical project: a deployable map-matching + path-prediction system trained **label-free** on raw fleet GPS (Porto; T-Drive for OOD). Architecture vocabulary: P1a transformer/attention encoder, P1b learned semantic vectorization, P2 latent-world-model RL, P3 label-free training. Success = product metrics (accuracy, latency, OOD, retraining cost).

## 2. Current best system

| Capability | Component | Number |
|---|---|---|
| Offline (batch) matching | **Hybrid Viterbi** — WM road-head log-prob + NK Gaussian emission, NK transitions | **0.8679** tolerant Hit@1, n=500 (2026-07-26, P2 32×32 ckpt @58% trained — new project best, was 0.8655 on 16×16) |
| Online (streaming) matching | WM road head + NK emission/transition ("hyb+topo", `matcher.py`) | **0.8287** match@1, n=500 (2026-07-26, P2 32×32 @58% — new project best, was 0.8122 on 16×16; jumps% not re-measured this run) |

Model: 2.6M-param decoder-light RSSM (h=512, 16×16 categorical latent), trained 60k steps on 200k Porto trajs (~8.2M fixes), 2 chained Kaggle T4 sessions.

## 3. How we got here (run history, compressed)

- **Track A (Runs 1–3, reconstruction RSSM):** faithful DreamerV3-style port posterior-collapsed across 4 experiment rounds — `h` freeloads on the teacher-forced road-embed channel via the reconstruction decoder (mechanism per Dai/Wang/Wipf ICML 2020). Pre-registered gate R2 failed at all checkpoints → hard stop. Honest negative, closed.
- **Track B (NK-HMM):** classical baseline, 0.8447 offline. Porto-learned semantic emission FAILED to beat raw geometry (in-domain and OOD −21.9pp on T-Drive) — recurring lesson: learned signal rarely beats geometry head-on here.
- **Track C (decoder-light WM, research2):** removed MDN decoder, GPS head z-only, road CE primary. Collapse eliminated (KL holds 8–9+ nats). Run 1 (15k steps) hit a curriculum/LR bug (L=64 phase trained at ~0 LR). **Run-2-XL** (60k steps, fixed schedule): match@1 0.695→**0.7684** (+7.3pp from schedule fix alone), hybrid Viterbi 0.8560→**0.8655**. Both matching gates PASS, prediction gate marginal, KL healthy. Per pre-registered exit rule: **WM track closed at 60k — no round 3** of the same lever.
- **Key structural finding:** WM emission alone loses to geometry (0.7684 vs 0.8447 offline) but is *complementary* — hybrid (WM + NK emission) is the first learned-signal win over pure geometry in the project. NK transitions over pure WM emission actively hurt (0.7268); the win comes from adding, not replacing.
- **RL actor (stage3):** underperforms the supervised road head for matching (0.593 vs 0.695) — physics-reward optimum ≠ nearest-road target. Reopened 2026-07-26 (see below) — track now CLOSED with stronger evidence than the original bounded attempt.
  - **Root-cause diagnosis (2026-07-26).** Reward-shaping mismatch confirmed: `r_topo`(w=2.0)/`r_head`(w=0.5) dominate `r_dist`(range ~[-5,0]) — actor optimizes topo/heading smoothness, not the eval metric's pure `d_perp` proximity. Reweight+refit frozen reward head (`head_only` config, local-CPU 7-config sweep + Kaggle CPU confirm): 0.593→0.6467 — helped, didn't close the gap to road-head (0.7653-0.8371).
  - **Early-stop / RL-unlearning probe (2026-07-26, local CPU, `~/.claude/jobs/.../actor_earlystop_probe.py`, reuses `ckpt/tune_head_only.pt`'s already-refit reward head, 20k-traj cache, 80-traj proxy eval, Run-2-XL 16×16 WM).** Tested whether match@1 peaks partway through RL fine-tuning before degrading. Result: **no sweet spot exists — step 0 (pure road-head warm start, zero RL) IS the peak** (match@1 0.7744, ≈ road-head ceiling 0.7830). From step 1, **monotonic decline, no recovery**: 0.7623(25)→0.7289(50)→~0.70(75-225)→~0.65-0.66 flat floor(300-800). Entropy falls in lockstep (1.42→0.48), no plateau-then-stable pattern. **Diagnosis: not noisy convergence to a plausible-but-worse optimum — systematic drift away from a known-good init from the first gradient step, the signature of reward-model overoptimization (Goodhart) against the frozen, imperfect learned reward head, not just a reward-weighting problem.** Early stopping cannot rescue this (there's nothing to stop early at — the actor's true optimum under this training scheme is "don't train it").
  - **Verdict: actor track CLOSED, stronger evidence than the original bounded-attempt rule required.** `matcher.py`'s existing choice (road-head decode, no RL) is now doubly justified: the RL actor's own training dynamics prove untrained IS optimal under this scheme. A real fix (not more tuning) would require changing the mechanism — trust-region/KL-constrained fine-tuning against the road-head, or a better (non-overoptimizable) reward model — bigger investment, gated behind an actual product need for sequential decision-making (§7), none currently exists.

## 4. Capacity verdict (2026-07-11 diagnosis)

**"Architecture too small" is NOT the primary bottleneck.** Evidence-ranked bottlenecks:
1. ~~**LR-schedule confound**~~ **— REFUTED by experiment (P0, 2026-07-12).** Was ranked #1 (final ~20k steps ran at LR ≤1e-6→1.7e-10; plateau feared uninformative). P0 tested it: resume run2xl, flat LR 3e-5, +10.3k steps → match@1 0.7677 vs baseline 0.7692 (**−0.15pp**), road CE not lowered. The plateau is **genuine convergence, not a dead-LR artifact**; the "free win from LR re-warming" hope is dead. (The +7.3pp historical gain was real but from the Run-1→Run-2 curriculum-bug fix, a different lever.) Bottleneck is now signal/data or capacity — P1/P2 the live probes.
2. **Label-free signal ceiling** — road head trains on geometry-derived soft pseudo-labels (CE floor = target entropy, never measured); hybrid adds only +2.1pp over geometry; prediction metrics flat from step 5k under 12× more training.
3. ~~**Unused data headroom**~~ **— CONFIRMED REAL by experiment (P1, 2026-07-14), the "data-matched" assumption below was wrong.** Was ranked #3 on untested Chinchilla-direction arithmetic. P1 tested it: 400k→800k match@1 +1.93pp/doubling, ~2x the bar. 800k of 1.7M Porto trajs used — headroom remains to the full pool. **Now the top-ranked, evidence-backed bottleneck** — see §5 for the next run.
4. **Latent width (the one supported narrow variant)** — 16×16 latent is a 4× down-scale of DreamerV3's universal 32×32 default; caps fine-GPS decode (cl_gps ~0.54km); but KL uses only ~22% of latent capacity, so road-task width is not saturated. DreamerV3 scales monotonically 12M→400M and our 2.6M is below their smallest config — bigger-WM prior can't be ruled out, hence probes.
5. Raw parameter count — least evidenced; no overfitting anywhere (nothing degrades across 12 ckpts).
